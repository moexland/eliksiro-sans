# Eliksiro Sans

## 简览 | At a Glance

Eliksiro Sans是一款集成了械黑GB与一定IBM Plex Sans SC补充并修复少量既有问题的字体。本仓库为以Python实现的字体构建流程。

Eliksiro Sans is a typeface that combines Frex Sans GB (械黑GB) with supplementary characters from IBM Plex Sans SC, and fixes a few existing issues. This repository contains its build pipeline, implemented in Python.

## 特点 | Features

### 泛用性 | Versatility

尽管械黑GB的字表已经覆盖简体中文的日常需要，但在复杂的实际使用中仍会时有回退出现，造成明显的风格变化。为此，Eliksiro Sans借IBM Plex Sans SC补充未涵盖的内容，兼以调整码位映射，从而能够覆盖GBK的全部字符。补字本出同源，基本不牺牲风格的统一性，故此Eliksiro Sans适合审美要求稍宽但覆盖需求高的生产环境。

Frex Sans GB's character set covers the everyday needs of Simplified Chinese, but the varied text of real use still sends characters to fallback fonts now and then, with a visible change of style. Eliksiro Sans therefore fills in what Frex Sans GB does not cover from IBM Plex Sans SC, together with some adjustments to the code point mapping, so that it covers every character in GBK. As the added characters come from the same source, stylistic unity is largely kept, which makes Eliksiro Sans suitable for production use that needs wide coverage and can be a little less strict about looks.

### 修正变形 | Fixed Distortions

可变字体的中间字重由数个设计字重自动过渡生成。IBM Plex Sans SC与械黑GB中有5个字，各设计字重的画法未能一一对应，过渡时笔画随之扭曲乃至消失，IBM官方的静态字体亦未能幸免。为此，Eliksiro Sans逐一修正了这5个字，并在构建流程中检查全部字形，以防同类问题再现。

The intermediate weights of a variable font are generated by blending a few designed weights. In five characters of IBM Plex Sans SC and Frex Sans GB, the designed weights do not correspond to one another, so their strokes twist or even vanish in the blend; IBM's own static fonts are no exception. Eliksiro Sans corrects these five characters and checks every glyph during the build, guarding against similar problems.

### 圆点 | Bullet

械黑GB的圆点（•）直接借用了中点（·）的字形，比通常的圆点小得多，用作列表符号或网页上的着重号时都显得过小。为此，Eliksiro Sans改用IBM Plex Sans（IBM Plex的西文字体）的圆点，并放大到与械黑GB的西文字母相称。

Frex Sans GB's bullet (•) reuses the glyph of the middle dot (·), which is much smaller than a usual bullet, so it looks too small both as a list marker and as emphasis marks on the web. Eliksiro Sans takes the bullet from IBM Plex Sans, IBM Plex's Latin typeface, instead, enlarged to match the Latin letters of Frex Sans GB.

### 行距 | Line Spacing

在网页上使用时，默认行距（`line-height: normal`）的实现因浏览器而异：使用械黑GB时，Safari与Chrome为字号的1.0倍，Firefox为1.2倍，行与行几乎相贴。Eliksiro Sans调整了行距设置，使三者统一为1.5倍，汉字在行内上下居中（于macOS实测）。

When used on the web, the default line height (`line-height: normal`) is implemented differently by each browser: with Frex Sans GB it is 1.0 times the font size in Safari and Chrome and 1.2 in Firefox, leaving lines almost touching. Eliksiro Sans adjusts its line metrics so that all three give 1.5, with ideographs centred in the line (measured on macOS).

### 技术细节 | Technical Details

以下细节，留给爱刨根问底的读者。

For readers who enjoy the nerdy details:

- 行距：hhea与OS/2的上、下、行间距均为880、−120、500，USE_TYPO_METRICS保持开启；OS/2的win值按全部字形的边界设定，避免裁切。
- 码位映射：U+F995、U+F9E7、U+F9F1三个兼容汉字指向秊、裏、隣的字形，以补全GBK；U+22EF ⋯与械黑GB居中的省略号同形，IBM的源文件里没有这个字。
- 圆点：取自IBM Plex Sans的`bullet`，放大到1.05倍，与械黑GB西文相对IBM Plex Sans的放大比例一致。
- 格式：CFF2可变字体，字重100至700，含8个命名实例；另有供网页使用的WOFF2版本，字体相同，只是经过压缩。
- 网页切片：npm包`@moexland/eliksiro-sans`以Google Fonts的简体中文切片表为底，把字体切成两百余个WOFF2切片；拉丁字母、标点与全角字符全部并入最常用的第一片，使字距调整、标点挤压在它们之间照常生效。

<!-- 分开中英两个列表 | keeps the two lists apart -->

- Line metrics: ascender 880, descender −120 and line gap 500 in both hhea and OS/2, with USE_TYPO_METRICS on; the OS/2 win metrics come from the bounds of all glyphs, so nothing is clipped.
- Code points: the compatibility ideographs U+F995, U+F9E7 and U+F9F1 map to the glyphs of 秊, 裏 and 隣, completing GBK; U+22EF ⋯ looks like Frex Sans GB's centred ellipsis, as IBM's sources have no glyph for it.
- Bullet: IBM Plex Sans's `bullet`, scaled by 1.05, the factor by which Frex Sans GB's Latin enlarges IBM Plex Sans.
- Format: a CFF2 variable font, with weights from 100 to 700 and eight named instances; also as WOFF2 for the web, the same font compressed.
- Web slices: the npm package `@moexland/eliksiro-sans` slices the font into over two hundred WOFF2 files, starting from Google Fonts' Simplified Chinese slices; Latin letters, punctuation and full-width forms all go in the first, most frequent slice, so that kerning and punctuation squeezing work between them.

## 构建 | Build

需要[uv](https://docs.astral.sh/uv/)和git。

Requires [uv](https://docs.astral.sh/uv/) and git.

```bash
uv run eliksiro-sans fetch
uv run eliksiro-sans merge
uv run eliksiro-sans build
uv run eliksiro-sans package
uv run eliksiro-sans verify
```

- `fetch`：把上游源文件取到`upstream/`，并核对内容与预期一致。
- `merge`：把IBM Plex Sans SC的补充字形并进械黑GB三个母版的副本，做好各项修正，改用Eliksiro Sans的名称和度量，写到`work/merged/`。
- `build`：把它们编译成CFF2可变字体`out/EliksiroSans-VF.otf`，再压缩出供网页使用的`out/EliksiroSans-VF.woff2`，并附上`OFL.txt`和`FONTLOG.txt`。同样的源文件总是编出逐字节相同的字体文件。
- `package`：把字体切成网页用的WOFF2切片，配上CSS入口，写成npm包`out/npm/`。
- `verify`：把编译结果与上游字体比对：械黑GB部分对照官方字体，补充层在8个字重上对照IBM的静态字体，并检查全部字形的插值；另外核对WOFF2与OTF是同一款字体，以及npm包的切片不重不漏、与完整字体一致。

<!-- 分开中英两个列表 | keeps the two lists apart -->

- `fetch` fetches the upstream sources into `upstream/` and checks that their contents are exactly as expected.
- `merge` adds the IBM Plex Sans SC supplement to copies of the three Frex Sans GB masters, applies the fixes and gives them Eliksiro Sans's names and metrics, in `work/merged/`.
- `build` compiles them into the CFF2 variable font `out/EliksiroSans-VF.otf`, compresses it into `out/EliksiroSans-VF.woff2` for the web, and adds `OFL.txt` and `FONTLOG.txt`. The same sources always give byte-identical font files.
- `package` slices the font into WOFF2 files for the web and writes them, with a CSS entry, as the npm package in `out/npm/`.
- `verify` checks the built font against the upstream fonts: the Frex Sans GB part against the official font, the supplement against IBM's static fonts at eight weights, and the interpolation of every glyph; it also checks that the WOFF2 holds the same font as the OTF, and that the npm package's slices hold every code point once and match the full font.

<sub>在M1 Pro（10核）上实测：`fetch`下载约1.1 GB；`merge`约3.5分钟，内存峰值约4 GB；`build`约3分钟；`package`约15秒；`verify`约4分钟。</sub>

<sub>Measured on an M1 Pro (10-core): `fetch` downloads about 1.1 GB; `merge` takes about 3.5 minutes, with memory peaking at about 4 GB; `build` about 3 minutes; `package` about 15 seconds; `verify` about 4 minutes.</sub>
